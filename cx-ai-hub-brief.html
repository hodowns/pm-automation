Cisco CX · Internal Platform Brief

CX AI Hub
From Executors to Orchestrators

A governed AI platform that shifts every CX role — NCEs, architects, PMs, SDAs, and leaders — from manually doing work to directing agents that do it. One CLI. Every Cisco tool. Real telemetry.

The Vision

Three Shifts, One Direction

The platform is built around a single arc: more judging, less doing. It delivers this across three dimensions simultaneously.

1

The Work Shift

Executors→ Judges

NCEs stop hand-drafting configs. Architects stop writing HLDs manually. PMs stop assembling dashboards. Agents handle the rote; humans review, approve, and redirect.

2

The Surface Shift

7 portals→ 1 CLI

SharePoint, Cisco IQ, ServiceNow, Webex, DDA, Outlook — callable from one surface. The integration layer moves from the person to the platform.

3

The Intelligence Shift

Anecdotes→ Data

Every agent run produces telemetry. Best prompt patterns become skills pushed to all 660 laptops. Leadership sees real adoption — not surveys.

The Problem

Six Gaps We Can't Ignore

Despite significant AI investment, CX leadership can't answer basic questions about ROI, adoption, or risk — because the infrastructure to answer them doesn't exist yet.

No Usage Telemetry

We know token cost, not hours saved. No mechanism to track when agents run, who runs them, or what value they deliver.

No Efficiency Insight

Prompt quality, model selection, cache utilization — invisible. Skill gaps stay hidden; coaching opportunities missed.

No Governance

A read-only agent and one that modifies production infra are treated identically. No risk classification, no audit trail.

No Transformation Signal

Is the org actually shifting? No adoption tiers, no progression tracking, no readiness signals. Leadership has anecdotes, not data.

Fragmented Discovery

Useful agents live in GHE repos found through Webex threads. MCP servers documented across dozens of Cisco wikis. No catalog.

Configuration Friction

Found a useful agent? Manually edit settings.json, clone repos, configure env vars. Non-technical roles can't start at all.

The Platform

What You Actually Get

A web hub behind Cisco Duo SSO with eight pillars — plus an AI-powered search, role-based onboarding, and a live extension catalog consolidating all scattered Cisco sources into one place.

Plugins MCP Servers Agents Skills Collections Docs Stats Governance Console

AI-powered search: Type "what helps me audit a customer's BGP design?" and get ranked extensions with plain-English rationales — not a phone-book filter.

Role-based onboarding: Pick "NCE" on first login → the CLI auto-loads the tools senior peers actually use. Productive on day one, without 4 weeks of Slack DMs.

The CLI is the only AI surface: No separate chat UIs, no role-specific portals. Every capability is a Claude Code extension. The hub is the catalog and telemetry cockpit; the CLI is the runtime.

Architecture

How the Pieces Fit

A

Config Repo → Every Laptop

One GHE repo (CX-Engr/claude-code-config) holds the approved toolbox. A SessionStart hook syncs it to all 660 laptops automatically — no manual install, no drift. One PR adds or removes a capability org-wide.

B

Agents Wrap Existing Tools — Never Replace Them

Every approved agent is a thin wrapper over a Cisco IQ module: DDA (Documentation Automation), DRG (Requirements Gathering), RAIDN (Assessments), SLAM, DDS, SaC. An HLD request calls DDA through the MCP — it doesn't hallucinate a document.

C

LiteLLM Proxy → AWS Bedrock / Anthropic Claude

Every prompt passes through the proxy: per-user virtual keys, budget caps, model allowlist, audit logging, and redaction. Swap model providers with zero code changes — model choice is runtime config, not architecture.

D

Telemetry Closes the Loop

Managed hooks + Claude Code OTEL + LiteLLM OTEL feed the hub dashboard. Underused tools get pruned; overused ones get hardened; rogue behavior gets quarantined in one commit.

Measurement

Two Scores. One Story.

Leadership doesn't need 20 dashboards. Two headline numbers — computed from real telemetry, trendable weekly — tell the transformation story.

0–100

AI Intensity Score

Per person, team, and org. Composite of tokens consumed, AI-authored code, productive AI time, adoption tier, and efficiency. Answers: "How deeply is AI integrated into this person's work?"

0–100

Role Agentic Maturity

Per role. How much of this role is agentified? NCEs might score 78; PMs might score 12. Answers: "Which roles are ready — and which are the biggest investment opportunity?"

Supporting composites include: manager effect (which managers' teams adopt fastest), stuck users detector (active but tier-stalled 4+ weeks), ROI headline (spend vs. hours saved), and week-over-week flywheel momentum.

Governance

Every Extension Classified by Risk

A four-level autonomy ladder applies to every extension in the catalog. An admin can quarantine any extension in one commit — it drops from all 660 laptops within one session cycle.

Level 1

Read-Only / Drafts

Text, answers, file reads. No tool use. Example: status report generator, doc summarizer.

Auto-approved
Level 2

Reads Internal Systems

APIs, databases, repos — read-only, no writes. Example: config analyzer, Cisco IQ query.

Auto-approved
Level 3

Proposes Changes

Creates PRs, tickets, files — human in the loop at every step. Example: PR creator, deployment planner.

Admin review
Level 4

Bounded Autonomy

Takes action without per-step confirmation within defined limits. Example: auto-committer (branches only).

The Operating Model

How It Compounds Each Quarter

The hub, config repo, and governance form one self-reinforcing loop. Every quarter, the org floor rises automatically — without management intervention.

1

Engineering ships the toolbox

Config repo holds the curated default. SessionStart hook syncs to every laptop. No manual install, no drift across 660 machines.

2

Hub measures everything that runs

Managed hooks beacon every agent run, tool call, and skill invocation. Local state harvest sees what's installed — curated or otherwise.

3

Patterns surface from the data

Similarity clustering finds duplicates. "47 people built the same NCE config helper" becomes visible, not invisible repeated effort.

4

Best practice gets promoted

Curation pipeline lifts the strongest version into the catalog with author attribution. Governance review classifies risk by autonomy level.

5

Pushed to every laptop — loop restarts

Approved version distributed via config repo. Telemetry restarts on the new baseline. One person solves a problem once; 660 benefit immediately.

Hard Questions

Three Concerns, Already Addressed

①

"What about employee monitoring concerns?"

Privacy by Construction

No prompt content captured in MVP — hard block at the ingest boundary, not a policy. File paths, code, OAuth tokens never reach hub storage. SOC2-ready audit log from day one.

②

"What if Anthropic raises prices or a better model ships?"

No Vendor Lock-in

LiteLLM proxy as the abstraction layer. Swap Anthropic → Bedrock → Azure OpenAI → Gemini with zero code changes. Model choice becomes runtime config, not architecture commitment.

③

"How do we keep AI spend predictable?"

Cost Discipline by Design

Per-user virtual keys bound spend per individual. Budget alerts fire at 80% and 100% — team leads paged before keys are cut. The dashboard shows ROI, not just cost.
