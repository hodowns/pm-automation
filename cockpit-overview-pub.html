Why this exists

What it is

Claude Code is the interface. The Cockpit is everything beneath it.

Enterprise infrastructure

Claude runs inside Cisco's own AWS environment, with sign-in, usage tracking and spending limits built in.

Live system connections

Claude can reach the tools you already use, like Webex, Outlook and SharePoint.

A shared skills library

Workflows built by your peers, available to everyone, so nobody starts from a blank page.

Not claude.ai. Your conversations, files and customer data stay inside Cisco's AWS boundary.

Trust

Your project folders stay yours

What is a repo?

A project folder with built-in version history. Git records who changed what and when, and GitHub is the website that hosts these folders so teams can share them.

What the Cockpit does not read

The files in your project repos, such as meeting minutes, reports and customer notes. It only sees your Claude setup, not your project work.

One thing to watch

Skills and CLAUDE.md files are part of your Claude setup, so keep customer-specific details out of them.

Guardrails and budget

Credential files are blocked from model requests, and you get a push reminder after an hour. Everyone has a spending cap, with Webex warnings at 50%, 80% and 100%.

Staying up to date

It updates itself

  • Automatic: every time you start Claude Code, it picks up the newest skills, rules and security policy.
  • Manual, if you ever need it: run cx-us-ps-claude update
  • Nothing else to remember. New approved tools reach everyone without reinstalling.
