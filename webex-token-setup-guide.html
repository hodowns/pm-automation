Webex MCP — 90-Day Auth Token Setup

How to authenticate the Webex MCP server so Claude Code can pull meeting transcripts, recaps, and attendee data. Takes about 2 minutes. Must be repeated every ~90 days.

Access Token
~14 days

Auto-refreshed silently in the background. You never need to touch this.

Refresh Token
~90 days

Keeps the access token alive. When this expires, run npm run auth again.

Re-auth Required
Every 90 days

One 2-minute browser click. Claude Code will give a 401 error as the reminder.

Before You Start

  • › Node.js installed — open a terminal and run node --version. If you see a version number, you're good. If not, download from nodejs.org (LTS version).
  • › The webex-mcp-oauth folder — located at C:\Users\[you]\webex-mcp-oauth\. It should contain auth-server.js, token.js, package.json, and a .env file.
  • › The .env file — must have WEBEX_CLIENT_ID and WEBEX_CLIENT_SECRET filled in. Get these from whoever set up your Webex OAuth app, or from the team's shared credentials doc. The file is hidden by default — make sure it's named exactly .env, not .env.txt.
  • › Port 8080 free — the auth server runs briefly on this port. If something else is using it, that program will need to be closed first.

Steps

01

Open a terminal in the right folder

Open PowerShell or Command Prompt. Navigate to the webex-mcp-oauth folder:

# Paste this exactly, replacing [you] with your username cd C:\Users\[you]\webex-mcp-oauth

Alternatively, open File Explorer, navigate to that folder, right-click in the empty space, and choose Open in Terminal.

02

Install dependencies (first time only)

If you've never run this before, install the required packages first:

npm install

Skip this step on subsequent re-auths — you only need to do it once.

03

Run the auth command

npm run auth

The terminal will print a long URL and show a waiting message. Something like:

╔════════════════════════════════════════════╗ ║ Webex OAuth — One-Time Setup ║ ╚════════════════════════════════════════════╝ ⚠️ The auth code Webex sends expires in ~60 seconds. 👉 Open this URL in your browser RIGHT NOW: https://webexapis.com/v1/authorize?response_type=code&...
⚠️ Act fast. The auth code Webex sends back expires in about 60 seconds. As soon as you see the URL in the terminal, copy it and open it in your browser immediately — don't pause to read this guide first.
04

Approve in your browser

The URL opens a Webex login/approval page. If you're already signed in to Webex, you'll land directly on the permission screen. Click Accept.

The browser will briefly redirect to localhost:8080/callback and then show:

✅ Authentication successful! Your tokens have been saved to tokens.json. You can close this tab and return to the terminal.

If you see an error instead, the 60-second window likely expired. Just run npm run auth again — it resets cleanly.

05

Verify the token was saved

Back in the terminal you should see:

✅ tokens.json saved. You are authenticated.

You can also open tokens.json in the folder — it should contain access_token, refresh_token, and two expiry timestamps. If the file is there with those four fields, you're done.

06

Test that it works

Ask Claude Code to pull a recent meeting transcript — for example: "meeting minutes [any recent meeting name]". If it returns transcript content instead of a 401 error, the token is live and working.

What Happens Automatically

You don't need to touch anything between re-auths. Here's what runs on its own:

↻

Access token auto-refresh (every ~14 days)

The Python transcript scripts silently call the Node refresh logic before every API call. If the access token is expired or close to expiry, it exchanges the refresh token for a new one and overwrites tokens.json automatically. No action needed.

✓

Transcript pulls on every meeting minutes run

Every time you run a "meeting minutes" command, Claude Code calls the Webex API to pull the transcript for that session. The token refresh runs as part of that call — so as long as you're running meeting minutes regularly, the token stays warm.

When to Re-Authenticate

Re-run npm run auth (Steps 1 → 6 above) in either of these situations:

A

Every ~90 days (calendar reminder)

The refresh token itself expires after approximately 90 days. After that, the auto-refresh stops working and every transcript pull will return a 401 error. Set a recurring calendar reminder 85 days after each auth to give yourself a buffer.

B

When Claude Code reports a 401 error

If a meeting minutes run shows [ERROR fetching meetings: 401 Client Error: Unauthorized], that's the signal the refresh token has expired. Run npm run auth and the error goes away.

Troubleshooting

401 Unauthorized
Refresh token expired. Run npm run auth to re-authenticate. Takes 2 minutes.
Auth code expired
You didn't click Accept fast enough. The code is valid for ~60 seconds. Run npm run auth again and open the URL immediately.
EADDRINUSE :8080
Port 8080 is in use. Close whatever is using it (check Task Manager for Node processes) or wait a moment and retry.
Missing .env variables
The .env file is missing or incomplete. Confirm the file exists in the webex-mcp-oauth folder, is named exactly .env (not .env.txt), and contains both WEBEX_CLIENT_ID and WEBEX_CLIENT_SECRET.
tokens.json not found
Auth hasn't been run yet, or the file was deleted. Run npm run auth from the start to create it.
node: command not found
Node.js isn't installed. Download the LTS version from nodejs.org and install it. Restart your terminal afterward.
